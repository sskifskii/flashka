# ADR-0002: Сессии аутентификации в PostgreSQL

Status: Accepted  
Date: 2026-10-14

## Контекст

MVP использует вход только по логину и паролю. Требуется возможность немедленно
завершить текущую сессию, а Redis и отдельный кэш явно исключены из стека. В
системе уже есть обязательная PostgreSQL.

## Решение

Использовать непрозрачный случайный session token в защищённой HttpOnly-cookie.
В PostgreSQL хранить только SHA-256-хеш токена, пользователя и срок действия.
Logout удаляет строку текущей сессии. Истёкшие сессии не участвуют в авторизации
и могут удаляться лениво без обязательного фонового процесса.

## Рассмотренные варианты

- **JWT без серверного состояния:** отклонён из-за усложнённого досрочного
  отзыва и отсутствия пользы для одного backend.
- **Redis:** исключён требованиями MVP и создаёт дополнительную обязательную
  инфраструктуру.
- **Сырой token в PostgreSQL:** отклонён, потому что утечка таблицы сразу дала бы
  действующие пользовательские сессии.

## Последствия

- Проверка авторизации требует короткого запроса к PostgreSQL.
- Logout и принудительное удаление сессии действуют сразу.
- Корректность не зависит от памяти конкретной реплики приложения.
- Cookie и запросы изменения состояния требуют CSRF-защиты, описанной в
  архитектуре.

## Условия пересмотра

Решение пересматривается при доказанной проблеме нагрузки на таблицу сессий,
переходе к нескольким независимым backend-сервисам или появлении нового способа
аутентификации.
