# MVP Roadmap

Этот документ — постоянная точка координации между рабочими сессиями. История чата не считается источником состояния проекта. Перед началом работы агент сверяет этот roadmap с файлами и `git status`. Перед остановкой он обновляет статус, а подробную точку продолжения — только для незавершённой работы.

## Статусы

- `Planned` — границы известны, реализация ещё не начата;
- `In progress` — идёт реализация;
- `Blocked` — продолжение требует решения или внешнего действия; причина обязательна;
- `Done` — выполнен облегчённый Demo Done; полное hardening допускается перед пилотом.

В один момент активен не более одного среза. Для SPEC-0004–0006 агент создаёт короткий spec и сразу реализует его; отдельный запрос или сессия для принятия spec не нужны.

## Общие технические задачи

Оформление README — `Done`: презентация продукта, бейджи и навигация; после публикации обновлены статус MVP и запуск из `main`, возможности оформлены списком; добавлен скриншот главной страницы `docs/images/home.png`, абзацы записаны без ручных переносов строк.

Исправление кнопок после сохранения карточки — `Done`: убран лишний верхний отступ, на узких экранах действия расположены вертикально на одинаковую ширину, на широких — по центру.

Следующие задачи не получают отдельный feature-spec. Они добавляются в первый срез, которому необходимы, и проходят тот же облегчённый Demo Done:

- CI, форматирование, линтеры и команды сборки;
- Исправление E2E после обновления редактора и дерева папок — `Done`: точные селекторы, закрытие мобильного меню, ожидание сохранения переноса карточки и отдельный backend для Playwright; все 6 desktop/mobile-тестов проходят.
- локальная PostgreSQL и конфигурация окружения;
- Makefile или эквивалентные проверенные команды;
- health checks и структурированное логирование;
- валидация OpenAPI после появления первого endpoint;
- базовые security headers и проверка отсутствия секретов.
- Подготовка open source — `Done`: README, MIT, CONTRIBUTING, SECURITY, шаблоны Issues/PR и защита локальных файлов; лицензия согласована в npm и OpenAPI. По запросу пользователя конфигурация Dependabot удалена; автоматические обновления версий отключатся после попадания изменения в `main`.

## Правило рабочих сессий

Целевой режим Fast MVP — один главный агент без субагентов и отдельного review. Он реализует минимальный happy path, обязательные инварианты и целевые тесты, доводит срез до `Done` по облегчённому процессу `DEVELOPMENT.md` и может сразу продолжить следующий связанный срез.

Если фазу невозможно закончить из-за технического прерывания или настоящего блокера, репозиторий оставляется собираемым, а точка продолжения обновляется. Та же фаза может быть продолжена в следующей сессии без изменения её границ.

Новая сессия начинает работу так:

1. применить инструкции `AGENTS.md` и перечисленные там источники;
2. проверить `git status`, последние изменения и фактическое наличие файлов;
3. открыть активный spec, если он уже существует, и этот roadmap;
4. не повторять успешные проверки, если влияющие на них файлы не менялись;
5. автономно довести текущую фазу до `Done` одним агентом;
6. продолжить с указанного ближайшего действия, а не перепроектировать уже принятое без новой причины.

Если фактический код расходится с записанной точкой продолжения, приоритет имеет проверяемое состояние репозитория. Roadmap сначала приводится в соответствие.
