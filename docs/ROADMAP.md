# MVP Roadmap

Этот документ — постоянная точка координации между рабочими сессиями. История
чата не считается источником состояния проекта. Перед началом работы агент
сверяет этот roadmap с файлами и `git status`. Перед остановкой он обновляет
статус, а подробную точку продолжения — только для незавершённой работы.

## Статусы

- `Planned` — границы известны, реализация ещё не начата;
- `In progress` — идёт реализация;
- `Blocked` — продолжение требует решения или внешнего действия; причина
  обязательна;
- `Done` — выполнен облегчённый Demo Done; полное hardening допускается перед
  пилотом.

В один момент активен не более одного среза. Для SPEC-0004–0006 агент создаёт
короткий spec и сразу реализует его; отдельный запрос или сессия для принятия
spec не нужны.

Названия и границы будущих срезов являются roadmap, а не принятой подробной
спецификацией. Если в ходе реализации понадобится изменить разбиение, это
фиксируется здесь с объяснением; уже выданные номера не переиспользуются.

После входа открывается Inbox без автоматического продолжения учебной сессии — `Done`.

## Общие технические задачи

Следующие задачи не получают отдельный feature-spec. Они добавляются в первый
срез, которому необходимы, и проходят тот же облегчённый Demo Done:

- CI, форматирование, линтеры и команды сборки;
- Исправление E2E после обновления редактора и дерева папок — `Done`: точные
  селекторы, закрытие мобильного меню, ожидание сохранения переноса карточки и
  отдельный backend для Playwright; все 6 desktop/mobile-тестов проходят.
- локальная PostgreSQL и конфигурация окружения;
- Makefile или эквивалентные проверенные команды;
- health checks и структурированное логирование;
- валидация OpenAPI после появления первого endpoint;
- базовые security headers и проверка отсутствия секретов.
- Подготовка open source — `Done`: README, MIT, CONTRIBUTING, SECURITY, шаблоны
  Issues/PR, Dependabot и защита локальных файлов; лицензия согласована в npm и OpenAPI.

## Правило рабочих сессий

Целевой режим Fast MVP — один главный агент без субагентов и отдельного review.
Он реализует минимальный happy path, обязательные инварианты и целевые тесты,
доводит срез до `Done` по облегчённому процессу `DEVELOPMENT.md` и может сразу
продолжить следующий связанный срез.

Если фазу невозможно закончить из-за технического прерывания или настоящего
блокера, репозиторий оставляется собираемым, а точка продолжения обновляется.
Та же фаза может быть продолжена в следующей сессии без изменения её границ.

Новая сессия начинает работу так:

1. применить инструкции `AGENTS.md` и перечисленные там источники;
2. проверить `git status`, последние изменения и фактическое наличие файлов;
3. открыть активный spec, если он уже существует, и этот roadmap;
4. не повторять успешные проверки, если влияющие на них файлы не менялись;
5. автономно довести текущую фазу до `Done` одним агентом;
6. продолжить с указанного ближайшего действия, а не перепроектировать уже
   принятое без новой причины.

Если фактический код расходится с записанной точкой продолжения, приоритет имеет
проверяемое состояние репозитория. Roadmap сначала приводится в соответствие.

## Точка продолжения

Все MVP-срезы и SPEC-0007–0009 завершены. Подготовка файлов к open source завершена:
добавлена согласованная пользователем MIT, лицензия синхронизирована в README,
CONTRIBUTING, npm и OpenAPI. Проверены ссылки, форматирование изменённых
Markdown/JSON-файлов, неизменность зависимостей и `make openapi-check` (успешно;
два предупреждения о 4XX у health endpoints). Ранее проверены ignore-правила,
secret check на тестовых ключах и доступная локальная история Git (26 коммитов,
283 уникальных blob): совпадений с выбранными шаблонами секретов нет.
`npm audit --omit=dev` не нашёл известных уязвимостей. Полный CI, integration и
E2E в этой работе не запускались.

Следующее действие перед публикацией: перенести изменения из `mvp` в default branch или выбрать `mvp`
основной веткой GitHub; локальный `origin/HEAD` указывает на `main`, где только
начальный README. Перед публикацией учесть личный email автора в истории и
включить приватные отчёты об уязвимостях в GitHub. Видимость репозитория и история
не менялись.

Следующий этап перед пилотом — общий hardening: полный CI, миграционный цикл,
integration/E2E smoke и проверка основных desktop/mobile-сценариев.
