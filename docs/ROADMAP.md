# MVP Roadmap

Этот документ — постоянная точка координации между рабочими сессиями. История
чата не считается источником состояния проекта. Перед началом работы агент
сверяет этот roadmap с файлами и `git status`, а перед остановкой обновляет
статус и точку продолжения.

## Статусы

- `Planned` — границы известны, подробный spec ещё не принят;
- `Draft` — feature-spec создаётся или обсуждается;
- `Ready` — spec имеет статус `Accepted`, работа может начаться;
- `In progress` — идёт реализация;
- `Blocked` — продолжение требует решения или внешнего действия; причина
  обязательна;
- `Done` — spec имеет статус `Implemented`, Definition of Done выполнен.

В один момент активен не более одного среза. Следующий срез подробно
специфицируется после завершения текущего, чтобы ранние технические выводы не
делали будущие документы устаревшими ещё до начала работы.

## Общие технические задачи

Следующие задачи не получают отдельный feature-spec. Они добавляются в первый
срез, которому необходимы, и проходят тот же Definition of Done:

- CI, форматирование, линтеры и команды сборки;
- локальная PostgreSQL и конфигурация окружения;
- Makefile или эквивалентные проверенные команды;
- health checks и структурированное логирование;
- валидация OpenAPI после появления первого endpoint;
- базовые security headers и проверка отсутствия секретов.

## Правило рабочих сессий

Целевой режим Fast MVP — один главный агент на анализ, реализацию и self-review
без обязательных субагентов. Он доводит заказанный срез до `Done` по правилам
`DEVELOPMENT.md` и может продолжить следующий связанный срез в той же сессии,
если это входит в запрос пользователя.

Если фазу невозможно закончить из-за технического прерывания или настоящего
блокера, репозиторий оставляется собираемым, а точка продолжения обновляется.
Та же фаза может быть продолжена в следующей сессии без изменения её границ.

Новая сессия начинает работу так:

1. применить инструкции `AGENTS.md` и перечисленные там источники;
2. проверить `git status`, последние изменения и фактическое наличие файлов;
3. открыть активный spec, если он уже существует, и этот roadmap;
4. воспроизвести релевантные проверки из точки продолжения;
5. автономно довести текущую фазу до `Implemented` одним агентом по умолчанию;
6. продолжить с указанного ближайшего действия, а не перепроектировать уже
   принятое без новой причины.

Если фактический код расходится с записанной точкой продолжения, приоритет имеет
проверяемое состояние репозитория. Roadmap сначала приводится в соответствие.
