# Feature-specs

В этой папке хранятся нумерованные спецификации крупных вертикальных срезов.
Общие правила и критерии необходимости описаны в
[DEVELOPMENT.md](../DEVELOPMENT.md).

При создании или смене статуса spec обновляйте эту таблицу в том же изменении.

## Шаблон

```markdown
# SPEC-NNNN: Название функции

Status: Draft
Date: YYYY-MM-DD

## Цель

## Входит в задачу

## Не входит

## Пользовательский сценарий

## Бизнес-правила и инварианты

## Данные и API

## Ошибочные и граничные случаи

## Критерии приёмки

## План тестирования

## Нерешённые вопросы
```

Если раздел неприменим, кратко укажите это вместо молчаливого удаления. Перед
переводом в `Accepted` раздел «Нерешённые вопросы» должен быть пуст либо каждый
оставшийся вопрос должен явно не блокировать реализацию.

`Accepted` выставляет главный агент после проверки на противоречия и
тестируемость. Независимый review допускается только в случаях Fast MVP,
определённых в `DEVELOPMENT.md`, или по прямому запросу пользователя;
пользователь подключается при настоящем продуктовом блокере.
