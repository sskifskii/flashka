# SPEC-0003: Папки

Date: 2026-10-15

## Цель

Дать пользователю законченное управление деревом папок и возможность создавать, просматривать и переносить карточки в выбранной папке, сохранив `Inbox` неизменяемым системным корнем.

Связанные требования: `CARD-04`, `CARD-06`, `CARD-09`, `FOLDER-01`–`FOLDER-06` и `FOLDER-08`. Основа: `SPEC-0001`, `SPEC-0002`, разделы 4, 5, 7, 9 и 12 `ARCHITECTURE.md`.

## Входит в задачу

- полное дерево папок со счётчиками непосредственных карточек и карточек в поддереве;
- создание, переименование, перемещение и удаление пустой пользовательской папки;
- выбор папки для списка и создания карточек, перенос карточки при редактировании;
- OpenAPI, адаптивный frontend и риск-ориентированные unit, PostgreSQL integration, HTTP, component и E2E-тесты.

## Не входит

- учебная область и сессии, поиск, сортировка и массовый перенос;
- удаление дерева каскадом, восстановление папок и отдельная страница настроек;
- серверная пагинация дерева и оптимистические мутации.

## Пользовательский сценарий

- Коллекция показывает `Inbox` и вложенное дерево. Выбор узла загружает только его непосредственные карточки и отражается в `folderId` URL, чтобы reload сохранял контекст.
- Рядом с деревом доступны создание дочерней папки, переименование, выбор нового родителя и удаление. Для `Inbox` действия изменения отсутствуют.
- Пользовательскую папку можно переместить, перетащив её на нового родителя; явная форма перемещения остаётся доступной альтернативой.
- Формы создания и редактирования карточки содержат необязательный выбор папки; по умолчанию новая карточка сохраняется в `Inbox`, а edit может перенести её.
- На мобильном дерево открывается кнопкой в панели; loading, empty, validation, conflict, not-found и network error имеют явные состояния и безопасный retry.

## Бизнес-правила и инварианты

- У пользователя ровно один корневой `Inbox`; его нельзя переименовать, переместить или удалить (`403 inbox_immutable`).
- Имя обрезается по Unicode `White_Space`, содержит 1–80 Unicode code points и сравнивается среди детей одного родителя без учёта регистра через `strings.ToLower`; конфликт даёт `409 folder_name_taken`.
- Родитель обязателен и принадлежит текущему пользователю. Папку нельзя поместить в себя или своё поддерево (`409 folder_cycle`). Backend ограничивает результирующую глубину десятью пользовательскими уровнями ниже `Inbox` (`422 folder_depth_exceeded`); adjacency list остаётся без SQL-лимита глубины.
- Мутации дерева одного пользователя сериализуются транзакционно; проверки владельца, цикла, глубины, уникальности и запись относятся к одной транзакции.
- Удаляется только папка без непосредственных карточек и подпапок; иначе `409 folder_not_empty`. Удаление не перемещает и не удаляет содержимое.
- Чужой или отсутствующий `folderId` во всех folder/card операциях выглядит как `404 folder_not_found`; SQL всегда фильтруется по session `user_id`.
- Счётчики дерева возвращают непосредственное и рекурсивное количество карточек. Порядок детей стабилен: case-insensitive имя, затем UUID. Дерево не пагинируется.
- Отсутствующий `folderId` при создании карточки сохраняет прежнее поведение Inbox. `GET /cards` без `folderId` также показывает Inbox. Перенос карточки не меняет её тексты, прогресс или `createdAt`, но меняет `updatedAt`.

## Данные и API

Новая миграция добавляет к существующей `folders` SQL-проверки непустой длины `name`/`name_normalized` до 80 символов и `updated_at >= created_at`; уже применённые миграции не меняются.

- `GET /api/v1/folders/tree` → `{ "root": FolderNode }`, где узел содержит `id`, `parentId`, `name`, `isInbox`, `directCardCount`, `totalCardCount`, `createdAt`, `updatedAt`, `children`.
- `POST /api/v1/folders` с `{ "parentId", "name" }` → `201 { "folder": Folder }`.
- `PATCH /api/v1/folders/{folderId}` принимает `name` и/или `parentId`; хотя бы одно поле обязательно → `200 { "folder": Folder }`.
- `DELETE /api/v1/folders/{folderId}` → `204` только для пустой папки.
- `GET /api/v1/cards?folderId=...` листает непосредственные карточки выбранной папки; без параметра — Inbox.
- `POST /api/v1/cards` принимает прежние поля и необязательный `folderId`.
- `PATCH /api/v1/cards/{cardId}` принимает прежние поля и необязательный `folderId`; хотя бы одно поле обязательно.

Изменяющие запросы требуют прежнюю CSRF-защиту, JSON остаётся строгим, UUID и время генерируются сервером.

## Ошибочные и граничные случаи

- Пустое/whitespace-only имя, 81 символ, неизвестное поле и невалидный UUID не приводят к записи; field errors привязаны к `name`, `parentId` или `folderId`.
- Конфликт имени после Unicode trim/lowercase проверяется при создании, переименовании и переносе; имя самой перемещаемой папки не конфликтует с ней.
- Перемещение под потомка, достижение глубины 11 и удаление папки с карточкой либо ребёнком отклоняются без частичного изменения.
- Исчезнувшая между загрузкой и мутацией папка даёт безопасный `404`; UI обновляет дерево. `401` использует общий выход на `/login`.

## Критерии приёмки

1. Пользователь создаёт вложенные папки, переименовывает и перемещает их; дерево и оба счётчика после reload соответствуют PostgreSQL.
2. Невозможно изменить `Inbox`, создать sibling-дубликат без учёта регистра, цикл, глубину больше 10 или удалить папку с карточкой/подпапкой.
3. Пользователь выбирает папку, видит только её непосредственные карточки, создаёт карточку сразу в ней и переносит существующую карточку.
4. Чужие папки и карточки недоступны через дерево, CRUD, list, create и move и не раскрываются отличимыми ответами.
5. OpenAPI, backend и frontend реализуют один строгий контракт; основной путь работает на desktop и 360 px с доступными controls и error/retry states.

## План тестирования

- **Unit:** Unicode-имя, построение/счётчики дерева, цикл и глубина.
- **PostgreSQL integration:** CRUD, sibling uniqueness, транзакционный cycle/depth guard, непустое удаление, tenant isolation, перенос карточки, recursive counts и migration `up/down/up`.
- **HTTP integration:** auth/CSRF, строгий JSON, коды ошибок, Inbox guard, чужие IDs и расширенный card contract.
- **Frontend component:** дерево/выбор, формы папок, состояния ошибок и выбор папки в card forms.
- **E2E:** регистрация → папка/подпапка → карточка в папке → перенос → запрет непустого удаления; desktop и критический mobile 360 px.
