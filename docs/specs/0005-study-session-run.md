# SPEC-0005: Прохождение учебной сессии

Date: 2026-10-15

## Цель и границы

Дать вошедшему пользователю пройти зафиксированный раунд: открыть оборот, оценить себя, продолжить после reload или повторного входа и при необходимости прервать сессию. Подробный итог, список ошибок и повторный запуск остаются в SPEC-0006.

## Правила

- Сервер отдаёт первую ещё не оценённую позицию; оборот скрыт до отдельного идемпотентного reveal. Чужая или отсутствующая сессия выглядит как `404`.
- Ответ допустим только для текущей открытой позиции активной сессии. Оценка — ровно `correct` или `incorrect`.
- Событие ответа, результат позиции, агрегаты карточки и завершение последней позиции записываются в одной транзакции с серверным UTC-временем.
- Повтор той же оценки возвращает сохранённое состояние без второго события; другая оценка для уже отвеченной позиции возвращает конфликт.
- Кнопки являются основным управлением; клавиши и свайпы вызывают те же действия. Горячие клавиши не перехватываются в полях ввода, случайный сдвиг не отвечает.
- Выход в коллекцию сохраняет активную сессию для продолжения; отдельное действие завершает её как прерванную.

## Критерии готовности

1. GET текущей/активной сессии восстанавливает позицию, progress и reveal после reload.
2. До reveal оборот и оценка недоступны на API и в UI.
3. Correct/incorrect меняют интервалы по лестнице ADR-0003 и переводят к следующей позиции.
4. Одинаковый повтор ответа идемпотентен, конфликтующий получает `409`.
5. Ответ, событие, карточка и состояние сессии атомарны и изолированы по `user_id`.
6. Кнопки, клавиатура и свайпы проходят один путь; при ошибке позиция не теряется.
7. Миграция, OpenAPI, целевые backend/component-тесты и затронутые проверки проходят.

Блокирующих вопросов нет.
