# SPEC-0004: Формирование учебной сессии

Date: 2026-10-15

## Цель и границы

Дать вошедшему пользователю экран настройки обучения: выбрать все карточки или папку с потомками, увидеть актуальную сводку, выбрать 1–100 карточек и создать раунд с зафиксированными составом и порядком. Прохождение, ответы и результат остаются в SPEC-0005–0006.

## Правила

- Preview принимает область `all` или принадлежащую пользователю папку; чужая и отсутствующая папка одинаково возвращают `404 folder_not_found`.
- Сводка содержит общее число доступных карточек, назначенные на `now` или ранее, новые и освоенные. Освоенность (`interval_days >= 30`) может пересекаться с назначенными карточками.
- Размер раунда — целое число 1–100. Фактический размер равен минимуму из запрошенного и доступного; пустая область не создаёт сессию.
- Сервер выбирает уникальные карточки: сначала due по раннему `due_at`, затем new в случайном порядке, затем early по ближайшему `due_at`; равные приоритеты перемешиваются внедряемым random source.
- Сессия и её позиции создаются одной транзакцией. Каждая позиция сохраняет bucket (`due`, `new`, `early`), поэтому дальнейшие перемещения карточек не меняют созданный раунд.

## Критерии готовности

1. Экран `/app/study/new` выбирает область и размер 5/10/20 или 1–100 и показывает preview с ожидаемым фактическим размером.
2. Папочная область включает все уровни потомков и не раскрывает чужие ресурсы.
3. `POST /study/sessions` фиксирует уникальный приоритетный список и возвращает идентификатор, requested/actual count и первую позицию.
4. Пустая область блокируется в UI и API с понятным действием добавить карточку или сменить область.
5. Миграция применяется вперёд, контракт OpenAPI актуален, целевые backend и component-тесты проходят.

Блокирующих вопросов нет.
